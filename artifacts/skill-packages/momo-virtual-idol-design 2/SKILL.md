# Momo 虛擬偶像設計

把「想做一個虛擬偶像」整理成可實作、可檢查的角色與體驗設計。以 Momo 為案例，教使用者建立自己的設計判斷。預設使用繁體中文，配合使用者的語言與交付需求。

## 先判斷這次要完成什麼

- **新角色企劃**：從定位、性格、視覺與互動開始，交付設計提案與素材需求。
- **既有角色延伸**：先閱讀設定與看過提供的角色圖，鎖定辨識特徵，再設計表情、換裝或動作。
- **互動原型**：先確認角色與必要素材，再實作使用者指定的範圍。
- **課程練習**：提供學員能操作的 Prompt、產出與觀察方式；依需要讀取 [學員設計表與練習](references/student-workbook.md)。

若使用者只要規劃，就交付規劃。若已要求實作且資訊足夠，完成必要規劃後繼續實作，不另外增加確認關卡。不要因套用本技能就新增遊戲、後端或直播系統。

## 釐清角色與用途

先從已提供的文字、圖片與專案找答案。只詢問會影響方向的缺口，優先合併成少量問題：

- 想讓誰喜歡這位角色？希望對方感受到什麼？
- 第一個接觸場景是官網、社群內容、影片、遊戲還是直播？
- 已有什麼設定與素材？這次要提案、繪圖規格還是可操作成果？

尚未決定的小細節可以提出有理由的暫定方案，標示為「提案」，與已確認設定分開。不要替角色捏造已發布作品、粉絲數、社群帳號或真人聲音。

## 建立可延伸的角色

用一句話連結「身份、性格、擅長的事、帶給觀眾的感受」。再補上日常喜好、弱點或反差，以及角色對觀眾的說話方式。

將抽象形容詞轉成可看見的行為。例如「努力但怕失敗」可表現在失誤時短暫沮喪、再次成功時恢復笑容。喜歡唱歌、跳舞或聊天，應能對應未來的內容形式。

產出至少一個登場、受挫與被鼓勵的情境，用表情、台詞和動作檢查是否像同一位角色。這些是設計示例，不代表需要實作三個功能。

## 定義視覺中固定與可變的部分

整理以下規則，數量以角色需求為準：

- **固定辨識**：輪廓、髮型或其他頭部特徵、五官比例、代表色、關鍵配件與畫風。
- **可變內容**：表情、姿勢、場景與服裝；說明變更時仍需保留什麼。
- **網站視覺**：背景、文字與操作色、字體層級、留白與裝飾，讓角色和介面各自清楚。

初版可先挑少量鮮明特徵，避免每個區域都堆滿符號。用小尺寸或剪影檢查辨識，再看完整細節。風格不預設為日系、粉色、女性或兔耳。

使用 Momo 教學或延伸 Momo 時，讀取 [Momo 案例](references/momo-case-study.md)。學習設定如何連到視覺與行為，不把 Momo 的造型當成所有學員的答案。

## 在製作前鎖定素材規格

依交付需求閱讀 [素材與動態規格](references/asset-and-motion-guide.md)，列出本次真正需要的圖像、表情或動作，並寫明用途、比例、背景、構圖、固定特徵與驗收方式。

已有角色圖時，先分析並重用；使用者要求保留原圖質感時，不自行換畫風或重新生成。使用者要新圖或允許生成時，以已確認的主視覺為參照，讓每次變體只改指定項目。圖片 Prompt 不等於已產出的圖片。

不要把網站上的圖片切換、網格變形或 GSAP 補間描述為已完成的 Live2D／3D 直播模型。若目標是直播，另外列出模型、綁定、追蹤與實際平台驗證所需交付；工具版本與匯入規格在實作時再查官方文件。

## 把角色個性轉成一個互動

用「觸發 → 角色回應 → 回到可操作狀態」描述第一個體驗，包含首次使用、重複觸發、失誤與完成。從角色的核心活動選一個小而完整的原型：招呼、選擇心情、節拍、對話或其他符合設定的操作。

為每段動態寫明目的。例如回應點擊、表現猶豫、慶祝完成；不要只列特效名稱。裝飾動態不能遮住必要資訊。需要滑鼠的互動，提供觸控與鍵盤途徑；減少動態時保留內容與操作。

網站實作先讀專案與現有設定，沿用使用者的框架與素材。Momo 的 Vue／GSAP 寫法是案例，不是所有虛擬偶像的技術要求。

## 交付與檢查

依本次範圍交付必要項目，不為單一修改重寫整份角色企劃：

1. **角色定位**：一句話定位、受眾、性格與代表行為。
2. **視覺規則**：固定辨識、可變內容與參考理由。
3. **素材需求**：本次需要的素材與一致性標準。
4. **第一個體驗**：操作流程、台詞、動態與完成回饋。
5. **驗證結果或方法**：完成了什麼、如何判斷、哪些仍是提案。

檢查角色在不同表情與動作中是否仍可辨識；台詞、行為與個性是否一致；使用者能否理解第一個操作。

有原型時實際檢查桌機、手機、鍵盤與減少動態狀態，特別看裁切、反覆觸發與返回流程。僅完成文件時回報文件檢查，不宣稱完成繪圖、模型、瀏覽器驗證或部署。
