# Idol Bloom｜偶像萌芽

從生活喜好建立自己的虛擬偶像，讓設定能轉成可辨識的造型、合適的場景與角色行為。預設使用繁體中文；依使用者本次需求交付企劃、圖片或原型。

## 先辨認目前階段

通常先有角色，再構思場景。讀取已提供的設定、圖片與對話，從目前階段接續，避免每次重新開始。

| 本次需求 | 工作重點 | 依需要讀取 |
| --- | --- | --- |
| 沒想法／新角色 | 喜好 → 身份與個性 → 外觀與代表台詞 | [學員練習](references/student-workbook.md) |
| 角色立繪／表情 | 建立或沿用角色基準，只改指定項目 | [立繪與生圖](references/illustration-and-imagegen-guide.md) |
| 已有角色，要場景 | 從角色身份、活動與現有畫風推導背景 | [主題與場景](references/theme-and-scene-guide.md) |
| 一次要整組 | 先完成角色基準，再構思與製作背景；依需求補合成圖與表情 | 上述兩份視覺指南 |
| 角色互動／動態原型 | 使用必要素材，完成指定操作 | [素材與動態](references/asset-and-motion-guide.md) |
| 想找設計參考／分析 Momo | 選與目前問題有關的來源 | [參考庫](references/reference-library.md)／[Momo 案例](references/momo-case-study.md) |

只做角色時，場景標為「尚未設計」即可；只做背景時，保留現有角色與文案。使用者要求整組時，可在同一次工作中依序完成，不為每張圖增加確認關卡。使用者說「先做角色，之後再做背景」時，交付角色階段後停止，不把後續階段當成已授權。

角色基準可以是足夠具體的文字設定，也可以是實際圖片。文字可用於場景企劃；要匹配既有立繪的畫風、光線與視角時，必須實際看過圖片。若使用者已指定場景或先從世界觀開始，沿用該方向建立角色，不強迫重走角色優先流程。

## 帶零基礎學員建立第一個角色

學員說「不會設計」「不知道」時，從一個容易回答的生活問題開始，例如想要陪伴、加油或幽默的感覺。已有喜好時直接使用；沒有方向時提出兩三個具體例子並推薦一個，將身份、外觀與代表行為說清楚。

學員仍不知道，或已請 agent 幫忙決定時，先做可修改提案。由 agent 處理配色、比例與素材規格，每項重要選擇用一句白話理由說明，不要求學員先填完整表格或理解專業術語。

角色階段先交付：暫定名字、一句介紹、性格與日常細節、固定外觀、代表台詞，以及本次需要的立繪規格或圖片。場景、按鈕、遊戲與直播模型依需求另做。使用者可以用「不要粉紅色」「想更活潑」修正，不需要重寫整份 Prompt。

區分已確認設定與 agent 的暫定提案。暫定小細節可用於已授權的製作，但不要宣稱使用者已確認，或捏造已發布作品、粉絲數與帳號。

## 保留角色基準

用一句話連結身份、性格、擅長的事與觀眾感受，再把性格轉成看得見的表情、姿勢與台詞。

固定角色的輪廓、頭部特徵、五官比例、代表色、關鍵配件與畫風；表情、姿勢、服裝或場景可依本次要求變動。沿用使用者最新確認的名字、原文與素材。風格、性別、物種與代表色不預設為 Momo 的答案。

已有角色圖時先查看。需要生圖的新角色先建立一張基準圖，再把實際圖像作為後續變體的參照；只做企劃時保留文字基準即可。保留原檔，修改另存版本。人物固定特徵與場景條件分開記錄，換場景不等於重新設計角色。

分階段交付時，附一段可直接沿用的「角色摘要」：身份、個性、活動、固定外觀、畫風、圖片位置或附件、已確認與暫定項目，以及尚未製作的部分。後續從摘要接續；新對話需要圖片才能判斷視覺時，請使用者提供該圖，不假裝能存取上次附件。

## 有場景需求時，再從角色推導

讀取 [主題與場景設計](references/theme-and-scene-guide.md)，先回答「這位角色會在哪裡、做什麼、邀請觀眾感受什麼」，再定地點、時間、天氣、道具、配色與構圖。世界觀可以先有概略設定，場景細節待角色建立後補上。

依現有立繪的光源、視角與比例安排背景，為角色和必要文案保留空間。背景的符號與細節服務角色身份，不要求每個場景重複所有配件或使用相同顏色。桌機與手機依實際用途安排構圖。

只做背景時，以背景匹配角色為優先。若指定場景與現有立繪的光線或視角衝突，說明差異並提出可用的場景調整；另做角色變體需符合使用者本次範圍，不默默重畫原角色。

## 製作本次需要的素材

只要企劃或 Prompt 時交付規格；要求生圖且工具可用時，完成必要設計後接著生成、查看與交付實際圖片。沒有生成工具時說明限制並提供可使用的 Prompt，不把描述標成圖片完成。

依 [立繪與生圖指南](references/illustration-and-imagegen-guide.md)選取本次素材。透明立繪、無角色背景、合成主視覺與表情是可組合的交付項目；五張整組是範例，不是預設配額。圖片分開保存，記錄實際尺寸、格式、透明狀態、參照版本與檔案位置。

工具可用性依當前環境判斷，不要求學員安裝 Momo 專案才能生圖。沿用既有圖片質感的需求優先；生成與編輯使用實際參照圖和工具支援的透明設定。已要求實作但素材未齊時，可用清楚標示的佔位素材測試操作。

## 有互動需求時，把個性轉成回應

讀取 [素材與動態規格](references/asset-and-motion-guide.md)，用「觸發 → 角色回應 → 回到可操作狀態」描述體驗。從角色活動選一個完整操作，讓表情、台詞與動態服務回應；包含反覆操作與完成後狀態。

網站實作先讀專案，沿用框架、素材與已確認版面。檢查觸控、鍵盤與減少動態時仍能完成操作。Momo 的 Vue／GSAP 是案例；姿勢換圖或局部變形與 Live2D／3D 直播模型分別交付和驗證。

## 參考與文件讀取

需要比較方向或解釋設計理由時，從 [參考庫](references/reference-library.md)挑與本次問題相關的來源，以「觀察 → 設計理由 → 原創轉化」說明。引用官方設定與技術要求時附直接連結；分析視覺要實際查看圖片。需要最新工具規格時查核官方文件，區分來源事實與自己的推導。

本 skill 的 `references/` 隨完整資料夾安裝，依 skill 所在位置讀取，不依學員專案 cwd 猜路徑。缺少延伸文件時，依本文完成可完成的範圍，說明缺檔並建議補齊完整安裝，不假稱讀過。

只有 Momo 程式案例使用內附文件的 GitHub 檔案連結查核；沒有網路時可讀案例摘要，標示未核對線上內容。新角色不依賴 Momo 的圖片與程式；案例網址不會自動匯入素材，也不是 skill 安裝來源。

## 依階段交付與檢查

交付本次完成的設計或圖片、選擇理由、沿用基準與下一階段可接續的摘要。只涉及角色時，不要求補齊場景或互動；只涉及背景時，不重交整份角色企劃。

- **角色／表情**：身份可辨識，固定特徵一致，肢體與配件完整，必要時驗證透明通道與切換對齊。
- **背景／合成**：符合角色活動，光線、透視與站位合理，角色與文字有可用空間。
- **互動原型**：實際檢查桌機、手機、重複操作、鍵盤與減少動態狀態。

回報「已提供規格」「已生成並查看」「尚待檢查」等實際狀態。文件檢查、圖片檢查、模型與瀏覽器驗證分開回報，未執行的項目不宣稱通過。
