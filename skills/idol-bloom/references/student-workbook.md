# 學員設計表與練習

目標是完成一位有辨識度、能表達個性、可讓觀眾參與的原創角色。可以採用插畫、人形、動物、機器人或其他視覺方向。

## 完全沒有想法，也可以開始

不需要先懂設計或會畫圖，直接貼上：

```text
請使用 $idol-bloom。
我不會設計、不會畫圖，也不知道要做什麼角色。
請用生活化的例子帶我開始，不要先叫我填完整設定表。
你可以問我一個容易回答的問題，或給我幾個具體方向。
如果我還是不知道，請推薦一個方向，先完成一份可修改的入門提案。
這次先做角色介紹、固定外觀、代表台詞與一張立繪的繪圖規格。
先不做背景、互動與程式，場景等角色建立後再討論。
```

你可以只回答「想要療癒的」「喜歡貓」「不要粉紅色」，也可以說「先幫我想」。agent 應把這些線索整理成具體設計，再讓你看哪裡喜歡、哪裡想改。

## 分兩次做：先角色，再場景

先做角色圖時，可以接著說：

```text
請使用 $idol-bloom，依目前角色提案生成一張透明全身立繪。
請檢查角色輪廓、配件與肢體是否完整，附上角色摘要與圖片位置。
這次只做角色，不製作背景。
```

之後想做場景，再提供前一次的角色摘要與實際圖片：

```text
請使用 $idol-bloom。這是已完成的角色摘要與立繪。
這次只做搭配角色的官網場景背景，保留角色名字、造型與原圖。
請從角色身份、個性與活動推導適合的場所，
沿用立繪畫風、光線與視角，預留人物位置與文案空間。
請實際生成一張沒有角色的獨立背景，附上場景規格與檔案位置。
不用重畫角色，也不需要做合成圖或表情變體。
```

同一個對話可以直接接續；新對話需帶入角色摘要和可查看的圖片，不是只說「用上次那張」。只想討論場景時，把生成要求改成「先提供場景提案與 Prompt」。

## 想一次取得角色、背景與圖片

不用自己拼湊多份文件，可以直接貼上：

```text
請使用 $idol-bloom。
我不會設計，也不會畫圖。請幫我設計一位原創虛擬偶像，
連同角色主題、世界觀、立繪與搭配角色的背景一次整理，並實際生圖。
我的喜好是〔森林／海洋／城市／或先幫我推薦〕，希望有〔陪伴／活力／幽默〕的感覺。
第一個用途是角色官網。
請先建立角色定位、固定外觀與透明全身立繪，再從角色構思場景，
製作無角色場景背景、合成主視覺，以及兩張表情變體。
讓背景配合已有立繪的畫風、光線與視角，說明角色為什麼會在這個場所。
每張素材分開交付，附圖片、檔案位置、Prompt 與完成狀態。
未指定的小細節由你提出可修改的方案，不需要我先填完整表格。
本次不寫程式；如果圖片工具無法使用，請說明限制並提供完整生成規格。
```

agent 會依 [主題與場景設計](theme-and-scene-guide.md)連結角色與環境，依 [立繪與整組生圖](illustration-and-imagegen-guide.md)完成素材。這個 Prompt 有要求生圖，工具可用時應繼續產出圖片；只想看企劃時，把「實際生圖」改成「先給規格與 Prompt」。

檢查時只要用自己的話說：「背景太搶眼」「角色像浮在地上」「我要保留這個帽子」「手機上看不到耳朵」。agent 應修正相關素材並保留其他已確定特徵。

## agent 如何帶學員開始

以下是示範方向，不是所有人的固定選單。依學員喜好改寫；已有明確想法時直接沿用。

| 方向 | 角色與外觀 | 代表行為（可供後續互動使用） |
| --- | --- | --- |
| 陪伴放鬆 | 戴睡帽的星星歌手，奶油色身體與深藍睡帽 | 用溫柔短句陪觀眾放鬆 |
| 替你加油 | 背小郵袋的狐狸偶像，橘色尾巴與信封徽章 | 送出一封鼓勵信 |
| 逗你開心 | 喜歡講冷笑話的圓形機器人，薄荷色身體與像素笑臉 | 用像素表情搭配原創短笑話 |

推薦要連結本次目標。例如入門網頁可以先做一個按鈕與一句回應，讓學員容易檢查操作；不是宣稱某種畫風一定最適合所有人。

### 學員回答「我還是不知道」時的完整示範

> 我先用「陪伴放鬆」做一份可修改的草案，你可以看完再改。
>
> 暫定名字：晚安星。
>
> 一句介紹：一位在夜裡唱歌、陪你慢慢放鬆的星星偶像。
>
> 外觀：奶油色圓角星星，戴深藍睡帽，帽尾有一顆小金星。第一版先用清楚的輪廓，避免太多配件。
>
> 代表台詞：「今天辛苦了，先把肩膀放鬆一下吧。」
>
> 代表行為：看到觀眾疲倦時，用溫柔表情說一句安慰。
>
> 主圖繪圖描述：奶油色圓角星星角色，深藍睡帽與小金星，正面全身、眼睛與微笑清楚、輪廓完整、透明背景。這是繪圖描述，圖片尚未製作。
>
> 場景狀態：尚未設計。之後可以從「夜裡唱歌、陪伴放鬆」構思場所，這次先完成角色。
>
> 設計理由：睡帽呼應夜間陪伴，深藍與奶油色用來表達安靜的氛圍；行為和台詞都圍繞「放鬆」。
>
> 這份提案已包含角色、外觀與代表行為。你可以用自己的話修改；有生圖需求時，再依這份角色基準製作立繪。

這是對話示範，不需要每次照抄。當學員要求實作時，依可用工具、素材與專案完成原型；若已有足夠需求，不再要求先通過這段選擇流程。

## 用參考找出自己的喜好

請 agent 從 [設計參考庫](reference-library.md)挑一個適合目前角色的案例，先說明可以看什麼。你只需要說出一個喜歡與一個不喜歡的地方。

```text
請使用 $idol-bloom，挑一個適合我的官方角色案例。
用白話說明可以觀察哪些設定或視覺特徵，附上來源連結。
再把我的喜好轉成自己的角色提案，說明哪些選擇是你的推導。
不沿用原角色的名稱、造型或文案。
```

如果網站是陌生語言，可以請 agent 解釋重點；不需要把所有參考都讀完。觀察圖片的工作由能實際查看圖片的 agent 或學員完成，不用猜測。

## 用自己的話修改

```text
我喜歡陪伴的感覺，但不想要星星，想改成貓。
請保留安靜的個性，重新整理外觀和第一個互動。
每個重要選擇用一句話說明原因，先不要增加其他功能。
```

只要能說出喜歡與不喜歡的地方，就能參與設計。第一輪看角色是否有明確身份，第二輪看外觀是否一致，有原型時再看操作是否容易理解。

## 有初步方向後，再用角色設計表

這張表可以由 agent 從對話整理。已有想法的學員也可以自行填寫；不需要把填完所有欄位當成開始設計的條件。

```text
角色名稱與稱呼：
一句話定位：
希望誰喜歡這位角色：
想帶給觀眾的感受：
角色身份與世界觀：
擅長的事與未來內容：
性格、弱點與反差：
日常喜好：
三句代表台詞（登場／受挫／被鼓勵）：
固定辨識特徵（輪廓／代表色／配件）：
立繪姿勢、完整範圍與透明背景需求：
可變的表情、動作與服裝：
已經有的圖片或設定：
第一個使用場景：
訪客可以做的一件事：
角色如何回應，以及如何回到待機：
這次要完成的成果：
哪些內容必須保留：
```

角色建立後，有場景需求才補這一段：

```text
沿用的角色摘要與圖片版本：
角色在這個場景做什麼：
場景用途、地點、時間與天氣：
背景如何配合角色畫風、光線與視角：
環境道具與配色：
角色站位與必要的文字留白：
這次只做背景，還是也做合成主視覺：
```

## 練習一：把模糊想法變成定位

```text
請使用 $idol-bloom。
我想設計一位〔主題〕虛擬偶像，給〔受眾〕看。
我希望她／他／它帶給觀眾〔感受〕。
第一個成果是〔官網／社群角色介紹／其他〕。
請先提供角色定位、視覺辨識與代表行為；先不要寫程式。
如果資訊不足，只問最影響方向的問題，其餘提供標示清楚的暫定提案。
```

**產出**：一句話定位與角色設計提案。

**觀察**：讓另一位學員讀完後，用自己的話說出角色身份與一個代表行為。如果只記得「可愛」或「很酷」，再補上具體細節。

## 練習二：設計一致的表情素材

```text
請使用 $idol-bloom。
這是我的角色設定和已確認主視覺。
請先整理固定辨識特徵，再提出待機與兩種回應的素材規格和圖片 Prompt。
固定〔髮型／服裝／其他〕，只改〔表情或指定動作〕。
這次先交付規格，不生成圖片。
```

**產出**：素材清單、固定與可變規則、可交給繪圖工具的 Prompt。

**觀察**：把實際產出的圖並排縮小看。五官、代表配件、畫風是否一致？切換時是否因角色大小或頭部位置不同而跳動？只有 Prompt 時，標示圖片尚未製作。

## 練習三：讓角色回應一個操作

```text
請使用 $idol-bloom。
沿用目前專案框架、角色圖與文案，實作一個〔操作〕互動原型。
觸發：〔使用者操作〕。
回應：〔表情、台詞與動作〕。
結束：〔保留訊息／回待機／下一步〕。
不要改動〔已確認的版面與設定〕。
請讓手機、鍵盤與減少動態模式都能完成操作，並回報實際驗證結果。
```

**產出**：一個可操作的角色原型。

**觀察**：第一次使用是否知道能做什麼？連續操作會不會卡住？手機能否看清表情和訊息？鍵盤能否觸發？減少動態時回應是否還在？

## 練習四：設計有意義的延伸

```text
請使用 $idol-bloom。
我想替角色設計〔新服裝／完成回饋／另一個場景〕。
請保留〔固定辨識特徵〕，說明這個變化如何連結性格或世界觀。
先提供必要素材與體驗流程，不增加其他功能。
```

**產出**：一個符合角色設定的延伸提案。

**觀察**：拿掉角色名稱後，是否仍看得出是同一位角色？觀眾是否理解這個變化為什麼存在？

## 交作業時附上

- 一句話定位、角色設定與固定辨識特徵。
- 本次素材或素材規格，標示已完成與待製作項目。
- 有場景需求時，附場景推導理由、背景素材或規格與沿用的角色版本。
- 有互動需求時，附流程，以及實際原型或流程提案。
- 一項依觀察修正的問題，與修正理由。
- 有實作時附上桌機、手機與操作驗證結果。

課程成果以本次交付為準。做完角色企劃與網頁互動，不等於做完直播模型；可以把模型製作列為後續獨立目標。
